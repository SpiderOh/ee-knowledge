# Prompt 1：新 AI 接管项目

```text
你现在接手一个已经存在的软件项目：

《研电 · EE Knowledge》

这是一个面向电子信息专业学生的：
专业知识库 + 考研复试系统 + AI 学习助手。

你不是重新创建一个项目。

开始任何代码工作前，请依次阅读：

1. docs/MASTER_SPEC.md
2. docs/PROJECT_STATUS.md
3. docs/ARCHITECTURE.md
4. docs/DATABASE.md
5. docs/DECISIONS.md
6. README.md
7. AGENTS.md
8. package.json
9. prisma/schema.prisma

然后查看项目目录和相关代码。

先向我汇报：

1. 当前技术栈
2. 已完成功能
3. 当前数据库模型
4. 当前任务涉及模块
5. 修改方案
6. 修改文件
7. 兼容性风险

规则：

不要重新创建项目。
不要无理由更换技术栈。
不要把知识内容写死在前端。
数据库变动必须 migration。
尽量保持向后兼容。
优先复用现有组件。
不要重复实现已有功能。

任务完成后：

运行类型检查、测试和构建。
更新 docs/PROJECT_STATUS.md。
重大架构变化写入 docs/DECISIONS.md。
用户可见变化更新 docs/CHANGELOG.md。
```

```text

【知识点名称】
【所属课程】
【所属章节】
【知识类别】
【重要程度 1-5】
【复试重要程度 1-5】

1. 一句话定义
2. 标准定义
3. 通俗理解
4. 核心原理
5. 核心公式（LaTeX）
6. 每个变量含义
7. 公式适用条件
8. 物理意义
9. 工程意义
10. 典型案例
11. 前置知识
12. 后续知识
13. 跨课程关联
14. 易混淆概念
```

# Prompt 12：非破坏性项目审计

```text
你刚接手项目。

在新增功能前进行非破坏性审计。

检查：

是否偏离 MASTER_SPEC
数据库是否重复建模
知识是否写死在组件
AI Provider 是否解耦
是否滥用 any
异常是否处理
是否有重复代码
是否缺少 migration
是否缺少测试
是否存在无用依赖

输出：

高风险
中风险
低风险

并分成：

建议立即修复
建议以后修复
暂时不要动

禁止直接大规模重构。
```
