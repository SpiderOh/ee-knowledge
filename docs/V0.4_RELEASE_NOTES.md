# EE Knowledge v0.4.0 Release Candidate

## Candidate scope

`v0.4.0-rc.1` freezes and regresses the Knowledge Learning Polish milestone. It combines the completed alpha.1 learning content, alpha.2 Quick Learning and alpha.3 mobile learning polish work. This is a release candidate, not the stable release.

### Included

- KnowledgePoint common mistakes and mastery criteria.
- Common questions with concise, standard and deep answers.
- Search and Knowledge Bundle v1 support for learning content.
- Quick Learning with `REVIEW > LEARNING > NOT_STARTED > MASTERED` priority, course scope and read-only selection.
- Mobile KnowledgePoint learning information, textbook context, narrow-screen Q&A and previous/next navigation.

No independent interview question bank, AI, RAG, PDF/Word import or v0.5.0 feature is included.

## Data and migration

- The v0.4.0 feature work used one additive migration: `20261003090000_add_learning_content_fields`.
- `KnowledgePoint.commonMistakes` and `KnowledgePoint.masteryCriteria` are nullable.
- Existing `InterviewQuestion` and `InterviewAnswer` relations remain the source for common questions; names and relationships are unchanged.
- The RC adds no migration, does not modify an existing migration, and does not delete or rewrite user data.

## Knowledge Bundle compatibility

Knowledge Bundle remains schemaVersion `1.0`. Learning fields and questions are optional, old v1 bundles remain importable, and existing question identity and partial-update semantics remain unchanged. No Bundle v2 is introduced.

## Quick Learning safety

Quick Learning chooses a point for reading only. It does not write `StudyProgress`, `ReviewRecord` or `PracticeAttempt`; the status-priority and course-scope rules are covered by `verify:quick-learning`.

## Upgrade from v0.3.0

For an existing self-hosted installation, stop services that write the database and make a cold backup before upgrading. Then update the checkout, install the locked dependencies, apply migrations, run the read-only integrity check, build and restart:

```powershell
npm ci
npm run db
npm run db:check
npm run build
npm run start:prod
```

Do not run `prisma migrate reset` or `npm run db:setup` against an existing personal database. The full backup and self-host procedure is in [`BACKUP_RESTORE.md`](BACKUP_RESTORE.md) and [`SELF_HOST.md`](SELF_HOST.md).

## Mobile boundary

The RC covers responsive web/PWA learning flow polish. It does not claim a native APK, offline-first writes or a second mobile database. Desktop and mobile use the same server-side SQLite canonical data source.

## Target environment limits

Local verification does not replace acceptance on Orange Pi/RK3588 or an x86_64 VPS, public Caddy HTTPS, Android installation, systemd timers, real USB/NAS secondary storage or physical 360/390/412 viewport inspection. These remain **Not tested in this environment**.

## Promotion gate

After PR review and a passing GitHub Actions run, the next step is v0.4.0 stable promotion. This RC task does not merge the PR, create a tag or create a GitHub Release.
