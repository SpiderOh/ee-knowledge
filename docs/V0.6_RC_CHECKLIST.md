## Data safety and restore

- Restore source integrity is checked before target mutation.
- Source and target journal, WAL and SHM sidecars fail closed.
- Existing targets receive a pre-restore backup.
- Restore uses a staged partial file, then checks post-restore integrity.
- Failed staged restores clean up the partial file.
- Scheduled backup covers Primary/Secondary integrity, retention, mount-drop revalidation and the different-filesystem rule.
- The implementation does not claim transaction-level atomic restore.

## Production and self-host

- `deploy:check` validates the Node runtime, `NODE_ENV`, absolute Linux SQLite path, database location, parent directory and auth configuration.
- `start:prod` binds `127.0.0.1:3000`.
- systemd loads `/etc/ee-knowledge/ee-knowledge.env` and runs `deploy:check` → `db` → `db:check` → `start:prod`.
- Caddy reverse proxies to the loopback service.
- Supported Node runtime is `20.x >= 20.16.0` or `>= 22.3.0`; Node.js 21.x is unsupported.
- `docs/V0.6_TARGET_ACCEPTANCE.md` separates automated checks from manual Orange Pi/RK3588, systemd, Caddy HTTPS, Android PWA and USB/NAS acceptance.

## Mobile and PWA

- Repository regression covers manifest, icons, maskable icon, mobile navigation hrefs, safe-area spacing, 44px touch targets, code/KaTeX/table overflow, knowledge navigation collapse and narrow admin/material-import layouts.
- These are static/mobile contracts. Real Android installation and 360/390/412px visual checks remain manual target checks.

## Authentication and learning loop

- Authentication remains single-user, environment-backed, private-by-default and session-cookie based.
- `verify:auth` and authenticated runtime smoke cover login, cookie flags, unsafe `next`, logout, private routes and admin API authorization.
- Review, practice, statistics and quick learning all remain green and are included in the full regression matrix.

## Personal Material Import

- Manual confirmation, atomic create-only writes, Bundle merge/upsert compatibility and no learning side effect remain unchanged.
- v0.6 adds no new import format and does not modify the material import implementation.
