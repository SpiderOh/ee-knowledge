# v0.6 Target Acceptance

本清单用于 v0.6.0-alpha.2 之后的真实目标环境验收。仓库 CI 只验证隔离的 production-like 配置、localhost runtime、模板和静态移动端 contract；以下 Orange Pi/RK3588、公开 HTTPS、Android PWA 与 USB/NAS 项目必须在目标环境人工执行，不能由 CI 代为标记通过。

## A. Orange Pi / RK3588 / Linux host

在目标主机记录：

```bash
uname -m
node --version
npm --version
sqlite3 --version
```

确认 Node 满足 `20.x >= 20.16.0` 或 `>= 22.3.0`，且不使用 Node.js 21.x。然后在目标机执行：

```bash
cd /opt/ee-knowledge
sudo -u ee-knowledge npm ci
sudo -u ee-knowledge npm run build
```

生产 preflight 不从普通 shell 直接运行；它由 systemd 服务在加载 production EnvironmentFile 后执行。

## B. systemd

systemd 从 `/etc/ee-knowledge/ee-knowledge.env` 加载生产变量，并按 `deploy:check` → `db` → `db:check` → `start:prod` 的顺序启动服务。不要在未显式加载 production EnvironmentFile 的普通 shell 中直接运行 `npm run deploy:check`；真实生产 preflight 由 systemd 的 `EnvironmentFile` + `ExecStartPre` 路径验收。

```bash
sudo systemctl restart ee-knowledge
sudo systemctl status ee-knowledge --no-pager
sudo journalctl -u ee-knowledge -n 100 --no-pager
```

如需主动触发一次完整 preflight，使用上面的 restart；不要无意义反复 restart。验收：服务为 `active (running)`；日志显示 `production environment valid`、migration deploy 和 `db:check` 成功；Next.js 只监听 `127.0.0.1:3000`。

## C. Caddy / HTTPS

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl status caddy --no-pager
```

在真实浏览器打开 `https://<domain>/login`，确认 HTTPS 证书有效、登录和退出可用。不要把域名解析、ACME、路由器端口转发或公网可达性写入仓库自动化检查。

## D. Backup

```bash
sudo systemctl start ee-knowledge-backup.service
sudo systemctl status ee-knowledge-backup.service
sudo systemctl list-timers ee-knowledge-backup.timer
```

若配置了 Secondary，再执行 `findmnt` 和 `df -T`，确认它是独立 filesystem。验收 Primary 已创建且 integrity check 成功；Secondary 只在配置并验证成功时记录。

## E. Mobile / Android PWA

在真实 Android 手机完成：

```text
登录 → 首页 → 课程 → 知识点 → 复习 → 练习 → 错题 → 统计 → 搜索 → 收藏 → 管理 → 资料导入 → 退出
```

使用浏览器的 Add to Home Screen / Install app 安装，确认 standalone 启动、底部导航、安全区和窄屏内容可用。仓库 CI 不执行真实 Android 安装，也不替代 360/390/412px Chrome 视觉检查。

## F. USB / NAS

若使用外部备份介质，记录挂载点、filesystem 类型和实际可写性；手动运行一次 backup service，确认 Primary、Secondary、integrity 和 retention 结果。不要把 USB/NAS 的实际状态写成仓库测试的 PASS。
