# EE Knowledge v0.5.0

## Personal Material Import

v0.5.0 provides a controlled single-user material import flow at `/admin/material-import`:

- Markdown/TXT UTF-8 extraction, PDF text-layer extraction and DOCX raw-text extraction.
- Manual editable confirmation of title, slug, course, body and source metadata.
- One file creates one new KnowledgePoint with atomic create-only semantics; an existing slug is never overwritten.
- Raw uploads are used only for this request and are not persisted. Import does not write learning data or call an external API.

## Safety boundaries

- Markdown/TXT maximum: 2 MB.
- PDF/DOCX maximum: 10 MB.
- Confirmed KnowledgePoint body maximum: 50,000 characters.
- Server Action transport ceiling: 12 MB.
- No OCR, legacy `.doc`, batch import, automatic splitting, image extraction or table reconstruction.
- PDF uses `PDFParse.getText()` and DOCX uses `mammoth.extractRawText`.

## Runtime and compatibility

- Node.js requirement: `>= 20.16.0` or `>= 22.3.0`.
- Direct parser dependencies remain `pdf-parse@2.4.5` and `mammoth@1.13.0`.
- v0.5 adds no Prisma migration; Knowledge Bundle schema remains `1.0`.
- The admin import page is private and requires the existing single-user authentication session.

## Safe update

For a self-hosted installation, back up before updating and keep the application stopped during the replacement:

```bash
sudo systemctl stop ee-knowledge
cd /opt/ee-knowledge
sudo -u ee-knowledge env DATABASE_URL="file:/var/lib/ee-knowledge/ee-knowledge.db" npm run db:backup -- --output=/var/backups/ee-knowledge
sudo -u ee-knowledge git pull --ff-only
sudo -u ee-knowledge npm ci
sudo -u ee-knowledge npm run build
sudo systemctl start ee-knowledge
sudo systemctl status ee-knowledge --no-pager
```

The deployment sequence is `deploy:check` -> `db` -> `db:check` -> `start:prod`. Run it against the target environment after reviewing the backup and rollback plan. Real Orange Pi/RK3588, Caddy HTTPS, USB/NAS and Android PWA acceptance remain target-environment checks.
