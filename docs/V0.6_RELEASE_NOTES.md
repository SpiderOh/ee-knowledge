# EE Knowledge v0.6.0

v0.6.0 is the Stabilization release for the single-user personal EE knowledge system, promoted from the verified v0.6.0-rc.1 candidate after full-system regression. It preserves the v0.5 Personal Material Import stable contract while strengthening data safety, self-host runtime checks and mobile/PWA behavior.

## Data Safety

- Restore source integrity is checked before target mutation.
- Journal, WAL and SHM sidecars fail closed for restore operations.
- Existing targets receive a pre-restore backup.
- Staged restore, post-restore integrity and failure cleanup are covered by regression checks.
- Scheduled Primary/Secondary backup integrity, retention and different-filesystem rules are verified.

## Self-host Stabilization

- Production environment validation covers the Node runtime, `NODE_ENV`, absolute SQLite paths, database location, writable parent directories and authentication configuration.
- systemd loads `/etc/ee-knowledge/ee-knowledge.env` and runs `deploy:check`, existing migrations, `db:check` and `start:prod` in order.
- The production server binds to `127.0.0.1:3000`; Caddy terminates HTTPS and proxies to the loopback service.
- Node.js support is `20.x >= 20.16.0` or `>= 22.3.0`; Node.js 21.x is unsupported.
- Production-like runtime smoke covers public routes, private routes, authentication and the main learning navigation on disposable SQLite.

## Mobile and PWA Stabilization

- PWA manifest, icons and maskable icon remain verified.
- Static mobile contracts cover navigation hrefs, safe-area spacing, 44px touch targets, code/KaTeX/table overflow, knowledge navigation and narrow admin/material-import layouts.
- Real Android installation and 360/390/412px visual checks remain manual target acceptance.

## Full-system regression

The RC regression matrix covers the learning loop, authentication, Material Import, content transfer, backup/restore, production preflight, PWA contracts, build and runtime smoke. v0.5 Material Import remains covered for Markdown/TXT, PDF text-layer, DOCX raw text, manual confirmation, create-only writes, Bundle compatibility and no learning side effects.

## Target acceptance

`docs/V0.6_TARGET_ACCEPTANCE.md` records the manual checks for Orange Pi/RK3588, systemd, Caddy HTTPS, Android PWA and USB/NAS. These targets are not represented as automated PASS results when they have not been connected and tested.

## No feature expansion

- v0.6.0 adds no new product feature, import format or PWA capability.
- v0.6.0 adds no Prisma schema change or migration.
- v0.6.0 introduces no new direct dependency and performs no dependency version upgrade.

## Safe update

For a self-hosted installation, keep the application stopped during the replacement and back up before updating:

```bash
sudo systemctl stop ee-knowledge
cd /opt/ee-knowledge

sudo -u ee-knowledge env \
  DATABASE_URL="file:/var/lib/ee-knowledge/ee-knowledge.db" \
  npm run db:backup -- --output=/var/backups/ee-knowledge

sudo -u ee-knowledge git pull --ff-only
sudo -u ee-knowledge npm ci
sudo -u ee-knowledge npm run build

sudo systemctl start ee-knowledge
sudo systemctl status ee-knowledge --no-pager
```

Do not run `deploy:check`, `db` or `db:check` from a normal shell without the production EnvironmentFile. The real production preflight runs through systemd's EnvironmentFile and `ExecStartPre` path. Existing migrations are applied by the systemd startup sequence; v0.6.0 adds zero new migrations.
