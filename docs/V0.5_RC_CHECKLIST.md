## Material import matrix

- Markdown, Markdown with GFM, and TXT: UTF-8 (BOM accepted), maximum 2 MB.
- PDF: text-layer extraction only, maximum 10 MB.
- DOCX: raw text extraction only, maximum 10 MB.
- Server Action transport ceiling: 12 MB.
- Confirmed KnowledgePoint body: maximum 50,000 characters.
- Invalid UTF-8, NUL bytes, empty text, invalid PDF/DOCX and legacy `.doc` are rejected.

## Extraction and write safety

- PDF uses `PDFParse.getText()` and destroys the parser in `finally`.
- DOCX uses `mammoth.extractRawText` only; no HTML conversion.
- No OCR, image extraction, table reconstruction, automatic splitting or batch import.
- Raw uploads and parser temporary files are not persisted and no external API is called.
- One file creates one KnowledgePoint after manual editable confirmation and source metadata review.
- Existing slugs are rejected. The final create-only write is atomic under a unique-slug race.
- Import does not write learning status, review, practice or statistics records.

## Bundle compatibility

- Knowledge Bundle schema remains `1.0`.
- Existing default merge/upsert behavior is unchanged.
- Material import uses the existing preview and import boundary; no schema or migration is added.

## Auth and runtime checks

- `/admin/material-import` redirects unauthenticated requests while preserving `next=/admin/material-import`.
- An authenticated session can read `/admin/material-import` with HTTP 200.
- Node.js must be `20.x >= 20.16.0`, or `>= 22.3.0`. Node.js 21.x is not supported by the frozen parser dependency contract.
- ARM64 / Orange Pi / RK3588 deployments must run `npm ci` on the target machine; copied `node_modules` are not supported.
- This checklist does not claim a real target environment has been verified.
